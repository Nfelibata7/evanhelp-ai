# 架构概览

EvanHelp 以 FastAPI 提供 API 和页面，以 LangGraph 承载有状态的客服工作流。业务分流、证据检查和写操作确认由明确的节点与服务边界控制，语言模型负责意图识别和受限场景下的回复生成。

## 请求处理

1. API 接收用户消息，载入会话摘要和最近对话。
2. 意图识别和指代消解补全当前问题。
3. 工作流按意图进入知识咨询、订单业务、退款处理、投诉升级或兜底路径。
4. 知识咨询通过向量与关键词召回，并可用 RRF 和重排组合结果；低置信度问题走兜底或进入复核队列。
5. 工具执行层校验参数、身份、权限、超时和重试策略；写操作在用户确认后提交。
6. API 以 SSE 返回文本与工具状态，并保留追踪和审计信息。

## 主要模块

| 路径 | 职责 |
| --- | --- |
| `app/api/` | 聊天、知识导入、反馈、复核和运营接口 |
| `app/graph/` | 会话状态、LangGraph 节点、路由和运行时 |
| `app/core/` | 模型客户端、检索、重排、意图、上下文与可观测能力 |
| `app/kb/` | Markdown 解析、结构切块、向量化和知识写入 |
| `app/tools/` | 内置业务工具、MCP 注册、执行和审计 |
| `app/db/` | SQLAlchemy 模型、数据访问和仓储 |
| `app/static/` | 聊天与运营管理页面 |
| `mcp_servers/` | 独立运行的物流和售后 MCP 服务 |
| `sql/` | 数据库初始化脚本与演示资料 |
| `scripts/` | 本地开发、运维、评估和分类器脚本 |

## 存储与外部服务

- **MySQL**：会话、FAQ、知识块、工单、审核队列及审计数据。
- **Milvus**：知识向量与检索索引。
- **SQLite**：LangGraph 本地会话检查点。
- **模型服务**：聊天、向量和重排分别通过 `CHAT_*`、`EMBED_*`、`RERANK_*` 配置。
- **MCP**：物流和售后工具可独立替换为真实业务连接器。
- **Langfuse**：提供可选的模型调用追踪；未配置时应用仍可启动。

## 可靠性边界

- 需要知识证据的回复先检索；证据不足时降低回答确定性并允许兜底。
- 工具的用户身份由服务端上下文提供，模型不能自行指定其他用户身份。
- 只读工具可配置超时与重试；写操作不自动重试，避免重复提交。
- 演示订单与物流查询使用样例实现。连接生产业务前，应替换服务端工具实现并配置访问控制、密钥管理和监控。

## 开发约定

本地密钥放在未跟踪的 `.env`；模板只保留占位值。数据初始化脚本按文件名前缀排序执行，新增脚本时保持唯一、递增的前缀。启动、建库和开发命令集中在 `Makefile`，页面入口与 API 路径登记在 `app/main.py` 和 `app/api/`。
